Yaaa 探索一种由自己掌握的个人 AI 系统：记忆可以审阅，工具可以替换，对外操作有明确的边界。这是一条逐步验证的设计方向。

## 为什么记录这些设计

一次对话可以解决眼前的问题。后续工作还需要知道：当时的约束是什么，为什么选择这条路，结论在哪个版本和范围内成立。这里把这些判断连同验证结果一起写下来。

## 从一次工作到可复用的知识

![从工作观察到审阅与复用的流程](/images/knowledge-flow.svg)

原始观察先保留来源，再形成候选知识。经过检查和审阅的结论，可以进入长期记忆、SOP 或 procedure。后来的验证如果推翻结论，也应留下修订记录。

| 记录 | 需要回答的问题                   |
| ---- | -------------------------------- |
| 设计 | 约束是什么，比较过哪些方案？     |
| 实现 | 对应哪个版本，改变了什么？       |
| 验证 | 在什么时间、环境与范围内检查过？ |
| 遗留 | 还缺什么，下一步由谁完成？       |
| 沉淀 | 经验怎样变成可复用的方法？       |

## 怎样阅读这个专题

设计文章展开取舍，工程日志记录带日期的变化，沉淀案例说明一种方法如何从一次工作中形成。文章会区分设计意图与已经验证的结果。[关于这个博客](/about/)介绍了写作方式。

这篇导读与日英版本用于建立相同内容的阅读入口。它们是随首版整理的编辑译文，本地 LLM 自动翻译管线仍在后续实施范围。
