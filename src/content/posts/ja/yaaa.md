Yaaa は、自分で管理できる個人向け AI システムを探るプロジェクトです。記憶はレビューでき、ツールは交換でき、外部操作には明確な境界を設けます。この設計方針を段階的に検証していきます。

## 設計の判断を記録する理由

一度の対話で目の前の問題を解決できても、次の仕事では制約、選択の理由、結論が成り立つバージョンと範囲が必要です。このブログでは、その判断と検証結果を一緒に残します。

## 一度の仕事から再利用できる知識へ

![観察をレビューと再利用につなぐ流れ](/images/knowledge-flow.svg)

観察には出典を残し、まず知識の候補として扱います。確認とレビューを経た結論を、長期記憶、SOP、procedure に反映します。後の検証で結論が変わった場合も、変更の記録を残します。

| 記録   | 答えるべき問い                       |
| ------ | ------------------------------------ |
| 設計   | 制約と比較した選択肢は何か？         |
| 実装   | どのバージョンで何が変わったか？     |
| 検証   | いつ、どこで、どの範囲を確認したか？ |
| 残作業 | 何が不足し、誰が次の作業を行うか？   |
| 知識   | 経験をどう再利用可能な方法にするか？ |

### 出典を追える参照

`sourceHash` は派生した内容と原稿のバージョンを関連付けます。次のコードはデータ形式の例であり、本番環境の実行記録ではありません。

```json
{ "article": "yaaa", "sourceHash": "example-revision", "status": "proposal" }
```

## この特集の読み方

設計記事では選択の理由を、開発記録では日付付きの変化を、事例では実践から方法が生まれる過程を扱います。設計の意図と検証済みの結果を区別します。[このブログについて](/ja/about/)も参照してください。

この導入記事には中国語・英語・日本語の入口があります。これらは初版に合わせて用意した編集翻訳です。ローカル LLM による自動翻訳パイプラインは、今後の実装範囲です。
